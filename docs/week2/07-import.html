Day 7 — Read a table and find out what it means

Lecture slides · Weekly self-check

Today’s question

We have lengths from 24 seedlings. Twelve independently potted plants were randomly assigned to a control group and twelve to a treatment group. Each plant was measured at the beginning and end of the same observation period. Can we bring the measurements into R without losing their meaning?

Open introcomputing.Rproj in the extracted course folder. Its data/ subfolder contains the supplied files and a README.md explaining them. A CSV is a text file in which commas separate columns. Its first line is a header naming those columns. The file is storage; importing creates an R object in memory.

Start from a known place

Create day07.R in the project root. Run:

getwd()
file.exists("data/seedlings.csv")

getwd() reports R’s working directory. It should be your extracted project folder, not the data folder. The second line should return TRUE. The relative path data/seedlings.csv means “inside data, find seedlings.csv, starting here”. Your full home-folder path differs from a classmate’s; this relative path can stay the same when they open their own project.

If file.exists() returns FALSE, inspect the folder in the file manager. A common problem is opening the ZIP rather than an extracted project, or an extra folder layer. Avoid solving this by inserting your personal absolute path into every line of code. Open the correct project instead.

Import and inspect

The readr package provides a table importer. Packages add functions to R; installing a package puts it on disk, while library() loads it for this session. The software setup page explains installation. Loading is needed again after restarting R.

library(readr)
seedlings <- read_csv("data/seedlings.csv", show_col_types = FALSE)
head(seedlings)
dim(seedlings)
names(seedlings)
str(seedlings)

read_csv() returns a table, displayed as a tibble. head() shows its first rows, not the complete dataset. dim() gives 24 rows and 4 columns. names() returns column names. str() describes structure and types: plant_id and treatment are text; the two lengths are numeric. Suppressing the type message with show_col_types = FALSE does not remove the need to check types.

Read the first row aloud: plant P01 is in the control group; its initial length was 25.7 mm and its final length 44.3 mm. Each row represents one plant, each column one variable. Two lengths from the same row are measurements on the same plant, not two independent plants.

seedlings$initial_mm
length(seedlings$initial_mm)
mean(seedlings$initial_mm)

$ selects a named column from the table, giving a vector. The length is 24. A mean without a unit is incomplete: the average initial length is measured in mm. The numbers cannot tell you whether the file used mm or cm; the dictionary and measurement protocol provide that information.

Missing is different from zero

A missing measurement is represented by NA after import. NA means not available. It does not mean zero length, no growth, or a control treatment.

example_mm <- c(12, NA, 18)
mean(example_mm)
mean(example_mm, na.rm = TRUE)
is.na(example_mm)

The first mean is NA: R will not silently pretend all measurements are known. The second is 15 mm, calculated from two observed values. na.rm = TRUE requests omitting missing values for this calculation. A report must still explain how many observations were missing and why, if known.

Your practical

  1. Import seedlings.csv and save the import and inspection commands in day07.R.
  2. Record in comments the row count, column count, column meanings, and units.
  3. Inspect tail(seedlings) to see the last rows. Find P24 and its treatment.
  4. Use sum(is.na(seedlings$final_mm)) to count missing final measurements.
  5. Import data/leaf-mass.csv into leaves, inspect it, and use its dictionary to explain what one row represents. Do not assume it has the seedling columns.
  6. Restart R and run your script from the top. The raw CSV files should remain exactly as supplied.
Hint: a function is not found

Run library(readr) before read_csv(). If loading fails because the package is not installed, use the setup instructions or ask for help. For column names, copy from names(seedlings); initial_mm and initial are different names.

Extended practical — inspect an unfamiliar table systematically

Allow about 90 minutes. A copied import line is not enough to establish that the right data arrived with the right meaning. Create day07-inspection.R and use it to investigate the new data/seedlings-transfer.csv. This simulated study has 18 independently potted seedlings, nine randomly assigned to control and nine to treated. Initial and final lengths are millimetres, measured seven days apart. Each row is one plant, not one independent measurement occasion.

  1. Open the course project, print getwd(), and check the relative input path with file.exists(). Import into a new object called transfer; keep the original seedlings object separate so that outputs from the two studies cannot silently overwrite each other.
  2. Use head(), tail(), dim(), names(), and str() on the imported table. Record what each command establishes and what it does not. For example, seeing six rows in head() does not mean the dataset has six observations.
  3. Check length(transfer$plant_id) and length(unique(transfer$plant_id)). The latter counts distinct identifiers. Compare them and explain why different counts would prompt investigation. Repeated IDs can be legitimate in a repeated-measurement design, so the study description—not a universal “duplicates are bad” rule—sets the expectation.
  4. Inspect unique(transfer$treatment) and table(transfer$treatment). Here table() counts the supplied labels. Check the expected group labels and nine records per group. Do not infer random assignment from the sorted row order; that information comes from the supplied study design.
  5. Count missing initial and final lengths using sum(is.na(...)). Use range(transfer$initial_mm) and range(transfer$final_mm) to inspect minima and maxima. Range is a check on recorded values; it cannot determine the intended units or establish that every plausible number was measured correctly.
  6. Make reports/transfer-import-audit.txt with the input path, dimensions, column types and roles, unique-ID count, group counts, missing-value counts, and units. State at least two things that required the data dictionary rather than a function call. Restart R and recreate the audit’s numerical checks.
Hint: use the object’s actual column names

A column request such as transfer$initial is different from transfer$initial_mm. Copy names from names(transfer) while learning. The intended table is 18 rows by four columns, with 18 distinct IDs and no missing initial/final readings. Matching these expectations helps identify the file but does not replace understanding its measurements.

Independent transfer — inspect quantities in different units

Plan 60–90 minutes. The supplied data/solutions.csv table contains six simulated calculation cases, not six independent treatment experiments. It lists solution IDs, a solute name, mass in grams, molar mass in grams per mole, and final total volume in millilitres. A mole is a unit of chemical amount; the supplied molar mass converts grams to moles. You will inspect the input today, then use these quantities in later calculation and report practice. No prior chemistry knowledge is needed.

  1. Import the table into solutions using a project-relative path. Before running str(), predict which columns should contain text and which should contain numbers. Compare the result with your prediction and explain why solution IDs and solute names are not measured quantities to average.
  2. Check dimensions, unique solution identifiers, the two solute labels, and the absence or presence of missing values. Read Q01 aloud: 0.2922 g of sodium chloride, supplied molar mass 58.44 g/mol, final volume 100 mL. Identify the meaning and unit of every number before doing arithmetic.
  3. Use range() on the numeric columns. Explain why the numbers for molar mass are not interchangeable with those for weighed mass, even though both types are numeric. A numeric storage type alone cannot authorise an operation.
  4. Compare these two supplied vectors in a separate part of the script: c(10, NA, 20) and c(10, 0, 20). Calculate their means and, for the first, the available-value mean using na.rm = TRUE. Record available and missing counts. Explain why using zero for an unavailable measurement invents evidence.
  5. Save reports/solutions-import-audit.txt describing the table, its units, and what you could calculate from the supplied inputs. Include the formula in words if helpful: amount = mass / molar mass; concentration = amount / final volume in litres. This is not a request to operate laboratory equipment.
  6. Ask a partner to run your saved inspection script from a fresh session. Have them identify which input generated each audit. If they see a table of 24 plants where the note promises 18, investigate the filename/object choice before changing the note to match whichever result happened to appear.

Check and retain: solutions.csv has six rows, five columns, six unique IDs, two supplied solute labels, and no missing inputs. The available-value mean of 10, NA, 20 is 15 from two observations; the mean of 10, 0, 20 is 10 from three. Your two audit notes should preserve that distinction.

Check your understanding

Why is the header not a plant? Why does the file’s name not tell R the units? Why should the script work from a classmate’s project folder?

Check your answers

The header labels columns rather than containing an observation. Units are metadata supplied by people; R only sees column names and values. The script uses relative paths and the same documented folder structure rather than your username. There are no missing final lengths in the clean seedling dataset.
