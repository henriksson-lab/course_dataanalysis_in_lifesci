Day 2 — Folders, paths, and the working computer

Lecture slides · Quiz · Weekly revision

Start by finding yesterday’s work

Open the file manager and find day01-notes.txt using the folders, rather than the editor’s recent-file list. Record the route you took; it will help you investigate “file not found” errors.

Our biological question is still about seedling growth. Today we organise the experiment so that someone else can identify the original observations and the results we produce from them.

Folders form a tree

A folder can contain files and more folders. We can draw part of our project as a tree. Indentation shows what is inside what:

introcomputing-course/
├── introcomputing.Rproj
├── report.Rmd
├── data/
│   ├── README.md
│   └── seedlings.csv
├── output/
│   └── seedlings-practice.csv
└── reports/
    └── day01-notes.txt

This drawing omits other supplied datasets. data and reports are neighbours: neither is inside the other. Their parent folder is introcomputing-course. That folder is the project root because it is the starting point for this project’s organisation. It is not the root of the entire computer.

In the file manager, open reports, go up to its parent, and then enter data. Watch the address bar on Windows or the folder path in Finder. In Finder, View → Show Path Bar can make the route easier to see.

A path gives the route to a file

A path describes a location. These examples are illustrations: your username and exact Documents location will differ.

Windows: C:\Users\anna\Documents\introcomputing-course\data\seedlings.csv
Mac:     /Users/anna/Documents/introcomputing-course/data/seedlings.csv
Linux:   /home/anna/introcomputing-course/data/seedlings.csv

An absolute path starts from the file system’s root or drive and specifies the whole route. A relative path starts from an agreed current folder. From inside introcomputing-course, data/seedlings.csv means “enter data, then find seedlings.csv”. From inside reports, that same relative path would ask for a data folder inside reports, where it does not exist.

This is why we need to know our current working directory: the folder from which a program interprets relative paths. Next lesson we will ask the terminal to print it. Relative paths will let us move a whole project without changing every filename in the analysis.

Give directions through the tree

Use the file manager to follow these routes.

  1. Start in the project root. Find the original seedling table.
  2. Start in reports. Find the practice copy in output.
  3. Return to the project root. Create a folder called practice.
  4. Inside it, create field-notes and figures.
  5. Copy yesterday’s note into field-notes and rename the copy seedling-observations.txt.
  6. Draw the new part of the tree. Close the file-manager window, reopen it, and navigate to the copied note using your drawing.

Prefer informative names with simple letters, numbers, and hyphens for this course. seedling-observations.txt is easier to interpret than new2.txt. We will learn to handle spaces too; simple names reduce avoidable typing errors.

I moved the whole project and now see two copies

First locate each copy and inspect its contents. A copy operation leaves the original in place; a move changes the location. Ask the teacher to help choose one working project before continuing.

What happens when you open a file?

Your laptop has several parts with different jobs:

Part Job in our seedling example
Storage, such as an SSD Holds the saved CSV and report between sessions.
Memory, or RAM Holds information the running application is using now.
Processor, or CPU Carries out instructions, such as calculating increases.
Operating system Manages files, memory, devices, and running programs; Windows, macOS, and Linux are examples.
Application Provides a particular tool, such as an editor, browser, or RStudio.

Opening a CSV lets an application read its saved contents. Editing text changes the application’s current working version. Saving writes that version to a file. An unsaved change may disappear when an application closes, even though the previously saved file remains. A process is a running instance of a program. An application installed on storage and a process using memory are related but different things.

Test the difference between editing and saving

Use practice/field-notes/seedling-observations.txt, not the original note.

  1. Open the practice note and add “The plants were measured twice.”
  2. Save, close, and reopen it. Confirm that the sentence remains.
  3. Add “This line is an unsaved experiment.” Close the editor and choose to discard the change if asked. Reopen the file and inspect the result.

Some editors save automatically or restore unsaved documents. If yours restores the sentence, discuss that behaviour with a teacher rather than treating it as proof that saving never matters. The important check is what is actually in the saved file, and where the editor saved it.

Where do local, cloud, and remote files live?

A local file is on the computer you are using. A cloud service may keep a copy elsewhere and synchronise it with your laptop. A remote Linux computer is another computer we will log into. Its home folder is separate from yours. Opening its desktop does not automatically copy your downloads to it.

An archive in the same folder as the originals is convenient for sharing, but it is not protection against losing the whole laptop. Keep another copy using the university’s supported backup or storage service once the teaching team identifies it. Check that a copy completed and that you can retrieve it.

Explain the computer through saved work

Use disposable notes under practice to compare saved files with application state and to test how moving folders changes paths.

  1. Draw the project tree on paper with data, output, reports, and your practice folder. Circle the project root. Mark the original seedling table, one derived practice copy, and yesterday’s audit note. Follow the tree in the file manager and correct any branch your drawing put in the wrong place.
  2. Make practice/memory-test.txt containing “version saved to storage”. Save, close, and reopen it. Then add “unsaved change” without choosing Save. Describe what happens when you close and reopen. If the application autosaves or restores the draft, record that behaviour.
  3. Save a second copy as practice/saved-copy.txt. Close the application, then open this ordinary file from the file manager. Identify what persisted after the program stopped. Explain why an installed editor, its running process, and a saved note are three related but different things.
  4. Create practice/map-a and practice/map-b. Put a copy of your note in map-a. Write directions to it starting from the project root, then write different directions starting inside map-b. Use the parent folder in your second route.
  5. Move the practice map-a folder into map-b, using the file manager. Predict how both written routes must change. Test them and revise your map. The note’s contents need not change when its address changes.
  6. Write reports/day02-investigation.txt with your before/after tree, what you observed about saving, and an explanation of why RAM capacity and disk capacity answer different practical questions. Include what you are unsure about, rather than treating the editor’s recovery feature as understood.
Hint: decide whether an observation concerns contents or location

If a sentence in the note changed, you are checking contents. If a route no longer reaches the same note, you are checking location. Copying can leave two sets of contents in two locations; moving changes the route. Use the file manager to inspect the actual folders before renaming or moving anything else.

Plan a portable laboratory project

Imagine your next laboratory exercise gives you a CSV of measurements, three photographs, and a protocol document. Design folders that keep these inputs recognisable alongside your analysis and report.

  1. Create practice/future-lab with data, images, reports, and output folders. Make three small plain-text placeholder notes in suitable folders, explicitly labelling them placeholders. Explain where actual image files would go.
  2. Copy data/seedlings-transfer.csv from the course project into this practice project’s data folder. Treat that file as its supplied measurement input. Write a README note at the practice root describing the folder roles and identifying that the copied input is simulated course data.
  3. Give the measurement file’s relative path starting at future-lab, then starting inside its reports folder. Draw the routes. Explain why a route containing your own account name would be inconvenient for a classmate.
  4. Make a separate copy of future-lab under another disposable folder you choose. Reopen its README and data through that copy’s tree. Does the relative route from the new project root still work? Compare with an absolute route written before copying. Record which project you will use for this test.
  5. Add three labelled boxes to your map: laptop, cloud storage if used, and a remote Linux computer. Draw only the copying or synchronising links you actually know exist. Put a question mark where service details are pending. A remote desktop is a view of another machine, not proof that two folders share contents.

Check and retain: your README, two folder maps, and day02-investigation.txt. From future-lab the measurement path is data/seedlings-transfer.csv; from its reports folder a route goes up to the parent before entering data. These are practice projects, so leave the original course project untouched.

Check your understanding

From the project root, what is the relative path to yesterday’s note?

reports/day01-notes.txt. From inside reports, its name alone is sufficient: day01-notes.txt. The file did not move; your starting location changed.

Does more RAM automatically provide more room for saved photographs?

No. RAM supports running work; persistent storage holds saved files. They have different jobs. We will see this again when R objects disappear after restarting R but the saved data file is still present.

Save today: add reports/day02-map.txt with a simple folder tree, the path to seedlings.csv, and one sentence distinguishing RAM from storage. Keep the practice folder for later navigation exercises.
