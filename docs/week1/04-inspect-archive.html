Day 4 — Unpack and inspect laboratory data

Lecture slides · Weekly self-check

Which seedlings received the treatment?

A lab partner has sent a small archive containing measurements and sample information. Before doing statistics, we need to establish what is in the archive and which files belong to the treated samples. We will do this with ordinary command-line utilities. The data are simulated for teaching.

The archive in this exercise is a small separate practice dataset with four samples. It is not the 24-plant dataset we will analyse in R. A manifest is a table describing which samples and files are present. Sample identifiers connect the manifest to the measurements.

Put the download in a known place

  1. Download lab-data.zip with your browser.
  2. Locate the downloaded file in File Explorer or Finder.
  3. In your terminal, run cd ~/introcomputing-shell, then pwd.
  4. Open that folder graphically using explorer.exe . in local Ubuntu on Windows or open . on Mac.
  5. Copy the downloaded ZIP into this workspace using the file manager. Do not assume your Windows browser downloaded it into Ubuntu’s home folder.
  6. Back in the terminal, run ls. Confirm that lab-data.zip appears.

On a remote computer, use the course’s supported transfer route when available. The browser’s local download is not automatically a remote file.

Look before extracting

From ~/introcomputing-shell, run:

unzip -l lab-data.zip

The -l option lists archive contents without extracting them. Identify README.txt, samples.tsv, and the measurements and field-notes folders. There should be four measurement files, S01 through S04. The displayed sizes and dates are information about the archive entries; do not type them.

Now extract:

unzip lab-data.zip -d lab-data
cd lab-data
ls
less README.txt

The -d lab-data option chooses the destination folder. Extraction creates ordinary files you can open; it does not remove the ZIP. In less, use Space to move down, arrow keys to move by lines, and q to quit and return to the prompt. A short file may already fit on one screen.

Extraction asks whether to replace a file

You have probably extracted into the same destination before. Stop and inspect the destination in the file manager. For this first run, choose a fresh destination name if necessary and use that name in cd. Do not automatically agree to replace files that may contain your work.

Read a table without changing it

Run:

head -n 3 samples.tsv
wc -l samples.tsv

head -n 3 prints the first three lines. wc -l counts newline-terminated lines. The supplied manifest has a header and four sample records, so the count is 5, not four biological samples. Tabs separate the columns in this TSV (tab-separated values) file. A CSV uses commas instead.

The columns are sample_id, treatment, and file. Follow the file path for sample S03:

head measurements/S03.csv

Before interpreting a number, use the README to find out what it measures and which units were used. The filename locates measurements; it does not explain their biological meaning by itself.

Search the manifest with grep

Run:

grep -F treated samples.tsv

grep prints lines matching a search. -F asks for a literal text match, so we do not need to learn pattern syntax. The supplied manifest should return two lines, S03 and S04, labelled treated.

This is text search, not an understanding of table columns or experiments. Searching for treated would also match untreated if that word were present. Our prepared labels are control and treated; the header does not contain the search word. Always inspect what a search actually selected.

Save a search, then count its records

grep -F treated samples.tsv > treated-samples.txt
less treated-samples.txt
grep -F treated samples.tsv | wc -l

> redirects the output to a file instead of displaying it. It replaces the contents if that output file already exists. Never use the input filename on the right side here. treated-samples.txt is a new text extract; the original samples.tsv remains unchanged. It has no header, because the header did not match our search.

The vertical bar | is a pipe. It passes the matching lines from grep to wc -l, which counts them. The result should be 2. The pipe does not need an intermediate saved file. Count lines only when lines really represent the records you intend to count.

Practical: preserve and organise a working copy

Still inside lab-data, run:

mkdir working
cp samples.tsv working/samples-copy.tsv
mv working/samples-copy.tsv working/manifest-practice.tsv
ls working

cp creates a copy; mv moves or renames an entry. Here only the practice copy was renamed. Confirm that the original samples.tsv still exists. Both commands can replace existing destinations, so check names before running them.

Use the file manager to create observations.txt inside working. Record: how many sample records there are, which two received treatment, and which measurement file you would open for S04. Add the distinction between the five manifest lines and the four samples.

A first look at the remote computer

The teacher will demonstrate SSH and remote desktop. SSH gives a terminal on another computer. A remote desktop gives a graphical workspace there. In either case, saved files can be on that other computer, even while your laptop displays the session.

When account details are available, follow the supplied instructions and try pwd and ls remotely. State aloud: “This command runs on ; this path is on .” If accounts are not ready, continue the local practical. Do not guess a login address.

Extended practical — audit the archive and the search

Allow about 90 minutes. Complete this in a newly extracted disposable copy, such as lab-audit, rather than mixing it into yesterday’s work. The archive contains four sample records, not the 24 plants in the R dataset. We use this small known structure to test what commands do before trusting a search on a larger laboratory export. Save an audit note with evidence and actual filenames.

  1. From the folder containing lab-data.zip, list its entries with unzip -l. Predict the extraction tree, then extract with unzip lab-data.zip -d lab-audit. Identify README, manifest, measurement files, and field notes. Listing an archive did not extract its entries; extraction did not remove the ZIP.
  2. Enter lab-audit and inspect samples.tsv with head or less. Follow each manifest path to its measurement file. Record which sample and units appear in that file. Confirm that S03 and S04 are the treated records and that their saved lengths differ; two matching labels are not identical samples.
  3. Run wc -l samples.tsv, then grep -F treated samples.tsv | wc -l. Explain both answers in words, including the header. Inspect the actual matched lines rather than assuming a count proves that the right records were selected.
  4. Copy the manifest to search-trap.tsv using cp. Open only that copy in the text editor, and replace S01’s control label by untreated. Do not change the actual manifest. Predict whether grep -F treated search-trap.tsv will select S01; run it and explain why literal text search is not a treatment-aware table operation. Save this as a demonstration of a limitation, not a corrected biological annotation.
  5. Save the original treated matches to treated-audit.txt. Copy that extract to extract-backup.txt. Now run grep -F control samples.tsv > treated-audit.txt only on this disposable extract. Compare the files with less: the name treated-audit.txt no longer describes its contents. > replaces output; it does not check whether the filename makes scientific sense.
  6. Restore the correctly named treated extract by rerunning the treated search. Write a note recording the misleading-name experiment and the corrected command. Never use samples.tsv itself as the output destination: shell redirection can truncate an input before the reader starts. Explain this hazard without experimenting on a raw input.
Hint: use known records to test the operation

In the unchanged fixture, wc -l samples.tsv gives 5 and the treated pipe gives 2. In the deliberately altered search-trap.tsv, the same substring search matches three lines, because untreated contains treated. A useful audit records both the command and the records selected. It does not silently rename those selected lines “three treated plants”.

Independent transfer — find a file discrepancy and report it

Allow 60–90 minutes. You are checking a received folder before analysis. The following discrepancies are created in a disposable copy so you can practise recovery; they are not claims that the supplied archive is faulty.

  1. Copy the extracted lab-audit folder using the file manager to a separately named received-check folder. Confirm you are in that copy in both terminal and graphical views. Locate its measurements/S04.csv and rename it S04-renamed.csv. Keep its contents intact.
  2. Starting from the copied manifest, check whether each listed relative file path exists by navigating and listing the relevant folder. Identify the one discrepancy. Explain why a manifest record can still exist while the named file cannot be opened. Do not solve it by deleting the sample record.
  3. Read the renamed measurement and identify S04 from its contents. Restore the original name using the evidence of the known deliberate rename. Recheck the manifest path, record the action, and distinguish a supported repair from guessing which similarly named file “probably belongs” to a sample.
  4. Repeat the treated search on the restored copy. While inside received-check, save treated-received.txt (its path from the parent is received-check/treated-received.txt); use a pipe to count its records and a reader to inspect their IDs. Identify which command wrote a new file and which merely displayed information.
  5. While still inside received-check, produce audit.txt (from the parent, received-check/audit.txt) with the original archive name, extraction location, header/record counts, search limitations, discrepancy, evidence, repair, and final check. Include the current computer, because the same path on a remote machine would describe different storage.
  6. Ask a partner to inspect your audit without hearing your explanation. They should be able to locate the restored measurement from the manifest and explain why a count alone was insufficient. Keep the original source archive and raw extracted manifest available for comparison.

Check and retain: both audit notes, the preserved source manifest, search extracts, and the deliberately labelled trap file. S03’s length is 42.4 mm and S04’s is 39.8 mm. Restoring a filename does not alter either measurement.

Check your understanding

Did grep change the manifest? Why does wc -l sometimes count a header?

grep reads the file; redirection saved its output separately. wc -l counts lines, not their meaning. The full manifest includes a header, while our saved matching lines do not. We must know the file’s structure to interpret the count.

Save today: treated-samples.txt, working/manifest-practice.tsv, and working/observations.txt in the extracted lab-data folder. Be able to show where the untouched archive and manifest are located.
