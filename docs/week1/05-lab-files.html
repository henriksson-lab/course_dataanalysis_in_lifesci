Day 5 — Share laboratory files, then meet R

Lecture slides · Weekly self-check

Repeat a useful workflow

Today you will repeat yesterday’s investigation with fewer prompts. Repetition helps make file handling a tool you can rely on. The biological task remains: identify the treated samples and prepare a small package that another person can understand.

We then meet R, which will calculate and plot the measurements. The terminal and R console are different places to enter instructions; recognising the difference will prevent a common beginner problem.

Practical 1: a fresh investigation folder

Return to your shell workspace:

cd ~/introcomputing-shell
pwd

Use commands from the previous lessons to do the following. Read the whole list once before starting.

  1. Create a fresh folder called day5.
  2. Copy lab-data.zip into it and move into day5.
  3. List the archive’s contents without extracting it.
  4. Extract it into a folder called lab-data inside day5.
  5. Enter the extracted folder and read the README.
  6. Print the treated sample records and save them as treated-samples.txt.
  7. Count the matching records using a pipe. Explain why the result is two.
Help me get started without doing everything

From the workspace use mkdir day5, cp lab-data.zip day5/, then cd day5. The slash after day5/ makes it clear that this destination is a directory. Use unzip -l lab-data.zip before unzip lab-data.zip -d lab-data. If a name already exists, inspect it before choosing whether to reuse it.

I cannot remember the search commands

Inside the extracted folder use grep -F treated samples.tsv. Add > treated-samples.txt to save the output, or | wc -l to count it. Do not redirect output into samples.tsv: that is the original input.

Practical 2: make a package another person can inspect

Inside the extracted lab-data folder, make a folder called report. Copy treated-samples.txt into it. Copy README.txt into it with the destination name context.txt. These copies keep the original files available.

Through the file manager, add report/findings.txt with four short statements: the number of samples, which received treatment, what the measurements mean, and what you have not yet analysed. For example, identifying a treated sample does not establish that its treatment changed growth.

Copy and rename commands 
mkdir report
cp treated-samples.txt report/
cp README.txt report/context.txt

Create your own findings text in a plain-text editor. Check its saved location with ls report before packaging the folder.

Create and inspect a ZIP package:

zip -r report-bundle.zip report/
unzip -l report-bundle.zip
unzip report-bundle.zip -d review
ls review/report

zip creates an archive. -r includes the folder’s contents recursively, including any nested folders. unzip -l lets you inspect the package, then extraction into review tests what a recipient would receive. You should find context.txt, findings.txt, and treated-samples.txt inside review/report. Open findings.txt from there and check it is readable.

An archive is a snapshot of the files included when it was created or updated. Editing the ordinary report/findings.txt does not automatically update the ZIP. Make a new clearly named package after making changes. An archive stored only next to its originals is still vulnerable if the whole computer is lost.

Practical 3: choose one transfer check

Choose the partner explanation below or the organic-laboratory file task that follows. They practise the same file skills; you do not need to do both.

Explain the seedling files to a partner

Take turns. Point to the original archive, extracted source files, selected records, your findings, and the final report archive. Explain the role of each. Ask your partner to locate a particular measurement file using the manifest. Check the path rather than relying on a file that happened to be open already.

If the supported remote environment is ready, repeat just the navigation and inspection part there. Use the provided transfer route to move a small file, then identify the local and remote copies. If it is not ready, this step waits; the local practical still stands on its own.

Or: find records in a small organic-laboratory inventory

An inventory is a list of samples. Our simulated organic-chemistry inventory already labels each sample with a class, such as alcohol or ester. These are supplied text labels; you do not need to recognise a molecular structure or know its reactions. The task is simply to find the records labelled ester.

  1. Download organic-lab.zip and locate it in your file manager. As on day 4, open ~/introcomputing-shell graphically and copy the download there. A browser download is not automatically in Ubuntu.
  2. Return to that workspace in the shell, list the archive before extracting, then extract to a fresh organic-lab folder and enter it. Read README.txt and DICTIONARY.txt with less before inspecting inventory.tsv.
  3. Use grep -F ester inventory.tsv to print matching records. Save them in ester-samples.txt and use a pipe to count them. Locate the saved extract in the file manager, then explain which file remained unchanged.
Hint: the same commands, different filenames 
cd ~/introcomputing-shell
unzip -l organic-lab.zip
unzip organic-lab.zip -d organic-lab
cd organic-lab
less README.txt
less DICTIONARY.txt
head inventory.tsv
grep -F ester inventory.tsv > ester-samples.txt
grep -F ester inventory.tsv | wc -l

There are four sample records plus a header. Two records match: O02 and O03. The header does not contain ester. This command matches literal text, not chemical structures or a particular table column. The extracted organic-recovery.csv is for later calculations; you do not need to analyse it today. If the extraction folder already exists, inspect it and use a fresh name.

Meet R and RStudio

R is a language and computing environment for working with data. RStudio is an application that provides an editor, an R console, and other tools around R. The editor holds saved instructions; the console runs them. A terminal is a shell prompt, not an R console.

Open RStudio using the R/RStudio setup instructions. If it is not installed yet, watch the demonstration and use setup support before week 2. In the R console, enter:

44.3 - 25.7

R should return 18.6: the increase in length of plant P01, in millimetres. The console might print [1] before the answer. That marks the position of the first displayed element; it is not part of the measurement.

Enter this small supplied example in the R console:

initial_mm <- c(25.7, 24.3, 18.0)
final_mm <- c(44.3, 32.3, 32.9)
plot(initial_mm, final_mm,
     xlab = "Initial length (mm)",
     ylab = "Final length (mm)")

The c(...) pieces collect three values. <- gives each collection a name. plot(...) makes a scatter plot: each point is one plant with an initial and a final length. We will learn these ideas carefully next week; today identify the axes and check that there are three points. This example includes only three plants, not the full experiment.

Do not paste cd, grep, or unzip at the R prompt. Likewise, do not paste R calculations into the Ubuntu shell and expect R to run them automatically. When a command fails, first identify which program is reading it.

From a plot to a report

The teacher will show a complete HTML report generated from saved measurements and an R Markdown file. Notice the biological question, code, figure with units, and a written interpretation. The goal is to make these together so that the report can be produced again when new measurements arrive. You will build your first version next week.

Extended practical — test a handover as the receiver

Allow about 90 minutes. A useful shared package must contain enough information for someone who was absent from the practical. Today you will make and test a second version of your small report package. This is ordinary laboratory file management; we are not introducing a version-control system or expecting you to memorise commands without references. Work on course practice material only.

Use previously unused ZIP names for each snapshot; if a suggested name already exists, choose the next unused version name before running zip. Updating an old archive can retain entries that are no longer in the source folder.

  1. Open the ordinary report folder from today’s earlier exercise. Inspect its findings note and selected records. Add a README that identifies the simulated seedling source archive, what one record represents, length units, which samples were selected, and the purpose of each included file. Avoid a note that merely says “these are the results”.
  2. From its parent directory, create report-v1.zip with zip -r. List the archive with unzip -l, then extract it to a new destination named receiver-v1. Navigate through that destination to find the report folder. Notice that the archived folder name can add another level after extraction.
  3. Open the extracted findings note in the file manager. Ask a partner to check a stated sample ID against the extract and manifest/source reference. If a source file is deliberately not included, the README must say where the recipient is expected to obtain it; do not imply that a shortcut transfers its target data.
  4. In the original ordinary report folder, add a dated correction sentence or clearer unit label. Do not change the received copy. Reopen the copy inside receiver-v1 and explain why it still contains the older text. A ZIP is a package made at a particular time, not a live connection to its source folder.
  5. Make a new report-v2.zip, list it, and extract it to receiver-v2. Check the revised sentence in that second received copy. Retain a brief change note so the recipient can tell which version to use without guessing from file modification times alone. Keep the ZIP outside the folder it packages.
  6. Save handover-check.txt in the shell workspace, recording the source folder, both archive names, receiver locations, checked sentence, and one problem that your first README did not explain well. State which computer holds these copies and whether you actually transferred a copy to another computer.
Hint: follow a concrete file, not the word “report”

For example, an extraction into receiver-v1 may place the note at receiver-v1/report/findings.txt. Inspect the actual tree. Editing report/findings.txt does not update that separate ordinary copy or the older ZIP. Repackage after correcting, then verify the newly extracted result; naming it v2 alone is not evidence that it contains the new text.

Independent transfer — prepare a new laboratory receipt

Allow 60–90 minutes. Choose the seedling archive or the organic-laboratory archive already used for your transfer check. Complete one route. The operations below are the same for both; chemistry background is unnecessary because organic classes are supplied text labels, and no product calculation is required here.

  1. Begin with a fresh extraction and read its README/dictionary. Write your own receipt listing the input filenames, their roles, and the known number of sample records. For seedlings this is four records in samples.tsv; for the organic inventory it is four records in inventory.tsv. Distinguish a line naming columns from an actual sample record.
  2. Define one selection question: treated seedlings, or inventory records with the supplied ester label. Predict the count, run the literal search, save its output with an informative filename, and inspect the IDs. Do not claim the tool interpreted a treatment or identified a molecular structure.
  3. Create a sharing folder containing your receipt, selected records, and a source note. Write one sentence explaining what a recipient could reproduce from that package and which original inputs they would still need. Include only course material; no personal files or account information.
  4. Package the sharing folder, extract into a new test location, and ask another student to answer the selection question from the received contents. Have them record the route they followed. Working alone, close the windows and act as the receiver after a break, using only the README you wrote.
  5. Make a short two-column note titled “shell or R?”. Classify pwd, grep -F, unzip, 44.3 - 25.7, and mean(c(12, 14, 16)). In RStudio, run the two R expressions if setup works. They should give 18.6 and 14 respectively; run shell commands in the shell instead. An error from the wrong interpreter does not mean the computer is broken.
  6. Finish with a recovery plan: how will you find your working folder tomorrow, which file will you open to continue, and where is the separately stored backup? If the university’s supported backup or remote access is pending, say so rather than pretending another local copy fulfils that requirement.

Check and retain: your tested sharing ZIP, receipt, handover check, and shell/R note. Both selection routes have two matching sample records in the supplied files. Next week’s R work will use the ordinary extracted course project, not an .Rproj opened from inside either shell-practice archive.

Check your understanding

Why inspect an archive after making it?

The name of the ZIP does not guarantee what it contains. Listing and extracting it checks the folder structure and the actual saved files a recipient gets.

Where should grep run, and where should 44.3 - 25.7 run?

Use grep in the terminal’s shell. Enter the calculation in the R console. The prompt tells you which program is waiting for instructions; learn to check it before entering a command.

Save today: a tested report-bundle.zip and the ordinary report folder. Add one sentence to findings.txt explaining how the package differs from its extracted contents. Repackage it if you want that change included in the ZIP. If you chose the inventory transfer check, also keep organic-lab/ester-samples.txt in the shell workspace.
