Day 21 — the same workflow on another computer

Lecture slides · Quiz · Weekly revision

Today’s question

You saved a report on a remote computer. Where is it, and how can you bring it back? Track the computer, folder, and copy of each file.

You need: the course project, a working local R setup, and the course’s remote-access instructions when issued. Save a short reports/remote-log.txt with the locations and checks below. Never record passwords or login codes.

Remote connection details are pending

HPC2N or another Linux environment will be used. The hostname, account route, authentication, remote desktop, transfer method, permitted execution location, and supported R application will be provided separately. Use those instructions for remote work. Until access is available, complete the local rehearsal below and mark the connection tasks pending.

1. Draw the locations before connecting

A path identifies a place on a particular computer. /home/anna/course and C:\Users\Anna\Documents\course need not contain the same files. Two identical-looking folder names on different computers do not synchronise.

Laptop                         Remote Linux environment
course project                 course project (a separate copy)
  data/seedlings.csv              data/seedlings.csv
  report.Rmd                     report.Rmd
  report.html                    report.html
          -- supported transfer -->
          <-- supported transfer --

SSH provides a shell on the remote system. A remote desktop provides a graphical workspace. These are interfaces, not automatic transfer services. The course instructions will confirm whether both sessions share the same home directory.

In your log, draw two boxes labelled laptop and remote service, with their actual project paths.

2. Connect, find your work, and return

Use the supplied SSH command from Ubuntu on Windows or Terminal on Mac. Its general form is:

ssh your-course-username@the-provided-host

Replace these placeholders using the service guide when issued.

Follow the supplied host-key verification and authentication instructions. After connecting, run these commands in the remote shell:

hostname
pwd
ls

hostname identifies the machine answering you; a service may use more than one machine. pwd identifies your current directory there. Record the service and folder. Make a practice folder using mkdir -p introcomputing-practice, then enter it with cd introcomputing-practice. Run pwd again.

Run exit to disconnect. You should return to the local shell, where pwd refers to your laptop. Reconnect using the supported route and find the practice folder again. Persisting files belong to saved storage, not to the terminal window.

3. Find the same designated folder from remote desktop

Open the remote desktop using the course guide. Locate the designated course folder in its file manager. Compare the full location with the SSH session. Do they share it? Record your observation rather than assuming they must.

Transfer the course ZIP using the supported upload or file-transfer method, extract it, and open its .Rproj in the provided R environment. If the service uses a browser-based R application, follow its course-specific project route.

In the remote R console, run:

getwd()
file.exists("data/seedlings.csv")

The second result should be TRUE. If it is FALSE, locate the project and its data before attempting analysis. A path from the laptop will not repair a missing remote input.

4. Produce one result and transfer it back

Open report.Rmd and render its HTML output using the provided R application. If R, packages, and Pandoc have been configured in the remote shell, the teaching team may instead ask you to run:

Rscript -e 'rmarkdown::render("report.Rmd")'

Run this only from the project root in the supported execution environment. It renders the saved document in a new R process. On Windows, continue using native RStudio locally; this command is for a configured remote shell.

Transfer the resulting HTML back to your laptop into a folder you can name. Open the downloaded copy in your browser. Record both paths and the transfer direction. An HTML result is convenient to read, but the source .Rmd and input data are still needed to reproduce it.

Local rehearsal while remote access is pending

In the file manager, copy the complete extracted course folder to a separately named introcomputing-rehearsal folder. Open that copy’s .Rproj, verify getwd(), render the report, and locate the HTML. This rehearses a portable project, not a remote computer. In your log write “local rehearsal only” and list the remote tasks still to complete.

Hint: the file exists, but R cannot find it

Check which computer R is running on, getwd(), and the actual path beneath that folder. Look for an extra folder created during extraction. Keep report paths relative to the project root.

Check your understanding

  1. Does exit delete the files you saved remotely?
  2. You rendered remotely, but local Downloads is empty. Is that evidence the render failed?
  3. Can a remote shell use a laptop’s data/ folder without any transfer or configured sharing?
Short answers
  1. No: it ends the shell/session; saved files remain subject to the service’s storage policy.
  2. No: the output may still be on the remote computer. Check its location and transfer it.
  3. Not automatically. File access must be explicitly provided or files transferred.

Audit a transferred project

Use the real service when available, or two clearly named local rehearsal folders. Record which route you used.

  1. Before copying anything, create reports/transfer-plan.txt. Name the source computer, source project path, destination computer, and destination project path. For a local rehearsal, label both as local and give different parent folders. List the intended input data/algae.csv, its dictionary, and the report source you will use.
  2. Open data/algae.csv in the original project without editing it. Read its dictionary: 24 separately grown cultures were assigned to reference or supplement, twelve each, and harvested once after seven days. A19 spilled before weighing, so its biomass is unavailable. The culture is the independent unit; the many cells within it are not independent cultures.
  3. Record three checks in your plan: number of culture records, number of available biomass measurements, and A19’s state. Use nrow(), sum(!is.na(...)), and filtering by identifier.
  4. Transfer or copy the complete project into the designated destination. Open the destination .Rproj, run getwd(), and repeat the checks there. Record both paths, the method, and the results in reports/remote-log.txt.
  5. Write a new plain-text note, reports/transfer-receipt.txt, in the destination copy. Include the date, the destination project path, the input filename, and the three checked results. Locate it through the supported graphical workspace as well as through the file listing.
  6. Bring that note back to the source using the supported route and open the returned copy. State whether you now have two independently stored copies. Close both applications and follow your written directions to locate the returned receipt.

Now investigate a deliberately stale copy. In a disposable copy of the project, change only the returned receipt’s text to say “second revision”. Save it, close the editor, and reopen both receipt copies. Does the other copy change? Keep both receipt copies and explain the observation. Identify which version you would transfer next.

Hint: compare contents as well as names

The algae table should have 24 records and 23 available biomass measurements. A19’s biomass remains missing. For small text receipts, open both in a text editor and compare the actual sentences. If you use R, the supplied expression identical(readLines("path-to-first-note"), readLines("path-to-second-note")) asks whether the text lines match; replace the two descriptions with your real paths. readLines() reads saved text, not an unsaved editor buffer.

Recover a misplaced result

Use a report you already know renders. Save directions that identify its output, source, and input.

  1. In the destination project, render the report once and locate its real HTML output. It may be beside its .Rmd or in a documented output folder. Write its full location and the time of your check in the transfer log.
  2. In the file manager, copy that HTML into a new folder named returned-results. Open that copy and check its location in the file manager or browser file address.
  3. Write the project location and a description of the desired result. Close applications, then follow those directions to find the HTML, source, and input without using recent files.
  4. Record one failed assumption or ambiguous direction, and repair the instructions. Include a concrete recovery sequence such as “identify the computer; open the project; find its output folder; inspect the file”.
  5. Check that an unchanged raw input has not been confused with the derived HTML. Explain which files must travel if the recipient needs to recalculate, rather than only read, the result. Add this distinction to your receipt.
  6. Save a final reports/transfer-audit.txt containing source, destination, checks, version decision, and one remaining limitation. If remote access is pending, include a separate list of the authentication, desktop, and transfer steps that still need real service practice. Local success cannot tick them off.

Keep: your plan, receipt, location log, and audit.

Before you finish: save your location log, mark any pending access-dependent steps, and identify the report copy you opened. End the desktop session using the service’s instructions. Next: DNA and images as data.
