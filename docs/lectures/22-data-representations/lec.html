Text, pixels, and measurements

Day 22 — familiar tools, different information

Data Analysis in Life Sciences

Different meanings, familiar representations

Our task: identify what each stored value represents.

Use invented DNA and an artificial image to practise vectors, tables, logical comparisons, and interpretation.

A file format gives bytes meaning

Renaming photo.jpg to photo.csv does not convert the contents.

A bit has two possible values; eight bits yield 256 patterns. One format may use a byte for brightness; another uses encoded characters. The extension helps an application choose how to read it.

One string is not forty vector elements

dna <- readLines("data/dna.txt")
length(dna)  # 1 stored string
nchar(dna)   # 40 characters in that string

length() and nchar() answer different questions.

bases <- strsplit(dna, split = "")[[1]]
length(bases)  # 40 separate letters

Run from the course project. The final newline is not another DNA base. strsplit returns a collection of results, and [[1]] selects the first. Supply this code rather than requiring list syntax as a new programming outcome.

Counts describe this invented sequence

table(bases) counts letters; it does not reveal a gene’s biological function.

Ask students to predict the result of replacing one A by a G. A falls by one, G increases by one, and the total remains forty. Preserve the source file and change an R object for this experiment. Meaning requires biological context.

An image can be a rectangular numeric table

0 means black; 255 means white on this teaching scale.

The source image has only values 25 and 210. One byte could store each intensity, but the CSV uses text digits plus delimiters and a header. The 64 values need not occupy only 64 bytes in that representation. No physical scale is provided.

A threshold is a stated comparison

Changing a threshold changes the question we ask of the same values.

Both images come from the actual supplied matrix. Because this constructed image has only two levels, separating its centre is unusually easy. Noise, lighting, and overlapping real objects would complicate interpretation.

Reuse logical values to count

pixels <- as.matrix(read.csv("data/pixels.csv"))
bright <- pixels > 100
sum(bright)   # 24
mean(bright)  # 0.375

TRUE contributes 1 and FALSE contributes 0.

The fraction is 24 / 64, not 24 independent organisms.

Here read.csv plus as.matrix supplies a simple numeric matrix. Normal biological tables still use read_csv. The calculation counts qualifying pixels; it has not identified cells or calibrated area in square millimetres.

A pixel is not an experimental replicate

  • An image position holds one brightness value.
  • Many positions can belong to one plant or one field of view.
  • A treatment assigned to one plant still has one treated plant.

What extra information would you need to interpret the bright object biologically?

Possible answers: acquisition context, physical scale, what was imaged, biological validation, and how treatment was assigned. Relate this to technical measurements and independent units from day 14, rather than introducing another test.

Prediction before code

Our only pixel values are 25 and 210.

What do these comparisons count?

sum(pixels > 50)
sum(pixels > 100)
sum(pixels > 220)

Ask before running: 24, 24, 0. A change in a threshold need not always change the count; it depends on which values occur. The threshold alone does not define a cell or specify physical area.

The question determines what to count

One string can contain 40 characters.

An 8-by-8 matrix contains 64 positions.

Neither size is automatically the number of independent organisms.

Ask students to name the represented thing before choosing length, nchar, dim, or a count of TRUE values. This is a transfer of familiar concepts rather than a survey of sequence or image software. Distinguish a file’s physical size in bytes from the number of meaningful values interpreted from that file.

Change one label; predict two counts

The original object and file can remain unchanged.

The sequence begins with A. Predict the total and two counts before running the replacement. Make a changed R object while preserving the raw file. Counts are numerical descriptions of this invented string, not evidence about the function of a real DNA sequence.

Create a changed object explicitly

bases_changed <- bases
bases_changed[1] <- "G"
table(bases_changed)
table(bases)

[1] selects the first element. Inspect both objects after the change.

Inspect bases and bases_changed to distinguish the original and modified values. Ask which operation would save the changed string to a file.

A fraction needs a stated numerator and denominator

GC fraction here = letters labelled G or C / all letters.

The original numerator is 18 and denominator 40; afterwards 19 and 40. This is a supplied definition with no molecular-biology prerequisite. In R, comparison with G or C uses a logical OR. It does not identify a gene, organism, or biological property beyond the count that has been defined.

Save a string, then verify the saved representation

writeLines(paste(bases_changed, collapse = ""),
           "output/changed-dna.txt")
changed_from_disk <- readLines("output/changed-dna.txt")
nchar(changed_from_disk)

The new saved string still has 40 characters.

paste with collapse joins elements into one string without a separator. writeLines saves that text. Reading it back checks the saved file, not only the current object. The new filename protects the supplied raw sequence. These lines are given operations to understand and adapt, not a new programming API survey.

Same positions, different brightness

A changed threshold answer need not mean a larger biological object.

The plot scale is fixed at zero to 255 in both panels. This makes the brightness change interpretable. Every matrix position stayed the same; adding thirty changed the numerical values. For this controlled example no value exceeds 255. Real acquisition and biological interpretation require more context.

Show the response to the stated threshold

A threshold is a comparison rule, not a discovered biological boundary.

For thresholds 0, 25, 100, 209, 210, 255 the counts are 64, 24, 24, 24, 0, 0. Only the values 25 and 210 occur, so the response is unusually simple. The plot shows a rule applied to known values; it is not a fitted model and does not validate a segmentation method for real microscopy.

Equality changes the selection

sum(pixels > 210)   # 0
sum(pixels >= 210)  # 24
sum(pixels > 220)   # 0
sum((pixels + 30) > 220)  # 24

Read the operator and the object before interpreting the number.

These are not inconsistent results. Strictly greater excludes equality; greater-or-equal includes it. Adding thirty changes the input while the threshold 220 stays fixed. These are the same logical distinctions used in row filtering, now applied to a rectangular collection of intensities.

Reorganising information differs from renaming a file

A new arrangement needs new delimiters and a header, not just a new suffix.

The practical asks students to create the tiny four-row CSV themselves and read it back. It is a format exercise, not sequence analysis. Merely renaming bases.txt to bases.csv cannot insert a table structure that was never present. Ask what one row represents in each version.
