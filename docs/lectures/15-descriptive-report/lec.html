Day 15 — A short descriptive report

Data Analysis in Life Sciences

One question, one short evidence trail

How does seedling growth vary among plants and groups?

This briefing consolidates descriptive analysis. The reader should learn the question, how the measurements arose, and what the observations show. An organic-yield report may replace this context, but is not an extra required report.

Give each part of the report a job

The plot shows the result; your words explain its meaning.

Walk through the drawing as a structure, not as a required page count or formatting template. Distinguish methods from results. A caption identifies the unit and visual encodings. Interpretation describes direction, variation and limits rather than repeating all printed output.

Choose and name the actual input

Use data/seedlings.csv for the complete core example.

  • 24 independently potted plants; 12 per group.
  • Initial and final lengths are measured in mm.
  • Growth is final minus initial length.
  • State explicitly if you choose the repaired incomplete file instead.

The complete and repaired datasets have different available counts. Keep those distinctions visible. The existing practical uses the complete file for the main report. The alternative organic-report.Rmd must identify independent synthesis runs and yield percentage units throughout.

Keep the source where its relative paths make sense

Save the .Rmd at the project root, not inside reports/.

Knit normally resolves relative data paths from the source report’s folder. Moving the source into reports/ would change where data/ points. An output_dir argument can place the generated HTML in reports/ while leaving the source at root.

Render from files, not from your memory of the session

Restart, then Knit without running console calculations first.

The report needs its own library calls, import and derived columns. An object existing only in the Environment pane is not a reproducible report dependency. Installation commands belong in setup, not inside an analysis that should run repeatedly.

Check the interpretation against the figure

“Mean treated growth was about 21.5 mm; control growth about 15.3 mm. Individual observations overlap.”

What would be wrong with “every treated plant grew more”?

We have described the sample; we have not estimated uncertainty in the difference.

The individual-point plot shows overlap. Keep SD as spread, not uncertainty in a group mean. In the optional organic context, standard mean yield 68.67% and modified 77% describe independent runs; higher yield does not verify purity or general protocol superiority.

A result should have a visible lineage

Trace each reported number back to a saved input and calculation.

Ask a reader to identify where the mean came from, which rows contributed, and which units apply. A report with an impressive table but an unidentified input is not complete.

The project file does not contain every dependency

Include the ordinary input CSV, not just a shortcut to its old location.

An Rproj provides context; it does not package data. Reproduction in a newly named folder tests personal paths and omitted files. Record any failure before fixing it, then rerun.

Keep claims at the level supported by the work

Descriptive work is useful even before a hypothesis test.

Repair sentences such as results were good or computer removed bad values. Identify a measurement pattern, a defined summary, or a documented correction. Current day15 reports do not quantify uncertainty in a treatment difference.

Adapt a structure, not an old conclusion

A changed title alone does not create a report about new observations.

The new source is seedlings-transfer.csv with 18 plants,9 per group. Replace old imports, descriptions, counts, and labels together. If using a previously saved analysis, recreate its objects inside the new report.

Inline results keep prose connected to code

A count or mean can be calculated inline after its object is created.

Literal source example: `r nrow(transfer)`

The sentence still needs a quantity, units, and interpretation.

Use escaped entities to display literal R Markdown code in these slides. During a student report render the inline expression executes. Installing packages or rendering the report from inside itself is not a solution to missing objects.

Do a reader review and an analyst review

Reader review: question, unit, outcome, figure meaning, conclusion.

Analyst review: input, checks, transformations, available n, regeneration.

A change log records the issue, correction, and rerun result.

The exercises include a revision of the selected report and a report on the second seedling study.

A short report can contain strong evidence

Keep one relevant table, one useful figure, and a specific interpretation.

Remove a redundant printout before removing a limitation or a unit label.
